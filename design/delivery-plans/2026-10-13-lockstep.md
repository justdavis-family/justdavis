# Lockstep Delivery Plan

## Overview

This plan sequences delivery of the five requirements under
  [Shared Content in Lockstep across Two Repositories](../product-vision/2026-09-04-design-process-sync.md)
  — [Agent-Assisted Sync of Shared Content](../product-requirements/2026-10-18-agent-assisted-sync.md),
  [Exact Comparison of Shared Content](../product-requirements/2026-10-18-exact-comparison.md),
  [Exact Delivery of a Sync](../product-requirements/2026-10-18-exact-delivery.md),
  [Declared Divergences and Shared Parts of Files](../product-requirements/2026-10-18-declared-divergences.md),
  and [Renamed and Moved Shared Content](../product-requirements/2026-10-18-renamed-and-moved-content.md) —
  into five milestones, one per requirement, following the
  [Lockstep Engineering Design](../engineering-designs/2026-10-13-lockstep.md).
Every milestone lands in `justdavis` as one pull request;
  `justdavis-private` receives each one's shared content through the sync itself, which is the point.

The main delivery risk is that **everything after the first milestone is speculative until the
  first has met real content.**
The design's first decision is to start from an agent's judgment and add determinism only where
  real use shows the need, so the first milestone is the whole use case,
  proven by bringing the two real repositories into sync,
  and the four that follow are thin, each extending the one before.
Before the second milestone begins, this plan is re-read against the notes the first one recorded;
  a milestone the notes do not justify is reshaped or dropped in a revision of this plan rather than
  built on anticipation.

Two things later milestones depend on are not in hand:

- **The `@`-import fix**, tracked in
    [#44](https://github.com/justdavis-family/justdavis/issues/44),
    which the reference check in the second milestone will fail without.
  It is its own small pull request, not a milestone here.
- **Five human decisions** the
    [divergence inventory](../analyses/2026-09-04-process-divergence-inventory.md) lists,
    which the first milestone makes and records, so that they are made once and in writing.

## Delivery Conventions

- **Each milestone ships as its own merged pull request in `justdavis`.**
  The shared content it adds reaches `justdavis-private` by running the sync there;
    the first milestone's bootstrap is the one exception, below.
- **The README is built incrementally.**
  Every milestone leaves `.lockstep/README.md` accurate for what exists at that point,
    and it says plainly which parts of Lockstep do not exist yet.
- **Every tool arrives with its tests**, built on fixture repositories per the design,
    and `lockstep:test` is wired into the root `ci` task in the milestone that creates it.
- **The first milestone's notes govern the rest.**
  The maintainer records, during real use, where the skill was slow, costly, or unreliable;
    each later milestone names the note that justifies it before it is built.
- **The only credential any step uses is the maintainer's own.**
  Neither repository holds a credential for the other, at any milestone;
    a milestone that would add one is a change to the design first.

## Milestones

### M1 — Agent-Assisted Sync, Proven on the Real Repositories

**Deliverable:** the `lockstep` skill and `.lockstep/README.md`, holding the declaration of what the
  two repositories share, present in both;
  and the two repositories' shared content in sync, in both directions, by the skill alone.

**Deferred:** every tool; anything exact.

**In scope:**

- `.lockstep/README.md`: what Lockstep is, the list of shared paths with plain-word notes beside
    the ones shared in part or intentionally different, how to run the skill, how to review what it
    opens, and what does not exist yet.
  A line in each repository's `CONTRIBUTING.md` points at it.
- `.claude/skills/lockstep/SKILL.md` and its supporting files: how the skill surveys the two
    repositories and both histories, mirrors upstream pull requests, keeps the halves of a rename or a
    move together, writes provenance into commit messages and descriptions,
    shows everything before creating anything,
    and requires the publication confirmation when the working repository is `justdavis`.
- The bootstrap: `.lockstep/` and the skill copied into `justdavis-private` by hand, once,
    as the last hand copy; every later change to them travels by the sync.
- Convergence: the skill run in `justdavis-private` against `justdavis`, the larger direction,
    then in `justdavis` against `justdavis-private`, with every decision put to the maintainer.
- The mixed files split where the design prefers and the maintainer agrees during convergence
    — the agent brief's general guidance into a rule, the pre-commit hook into one shared line —
    and those left unsplit noted in the README as shared in part or by judgment.
- The maintainer's notes on where the skill was slow, costly, or unreliable, in the pull request.

**Human decisions this milestone records** (from the inventory's recommendation):

- The two textual fixes, `supersede` and "delivery plans", are taken into `justdavis`.
- The centralized-configuration principle is adopted into `justdavis`;
    it is project-agnostic, and `justdavis-private`'s own earlier analysis recommended it.
- A dependency-audit workflow is adopted into `justdavis`, which now has Rust projects.
- The four repository-specific lines are generalized, except the label-automation issue link in the
    PR workflow rule, which is noted in the README as an intentional difference.
- The eight shared engineering principles take `justdavis`'s names and dates;
    `justdavis-private` renames its copies and updates its references in the same pull request.

**Acceptance criteria:**

- [ ] Both repositories hold `.lockstep/README.md` with the declaration, and the skill
        (from [Agent-Assisted Sync of Shared Content](../product-requirements/2026-10-18-agent-assisted-sync.md)).
- [ ] Run in each repository against the other, the skill opened pull requests mirroring the
        upstream changes, each with its provenance and on that repository's conventions
        (from [Agent-Assisted Sync of Shared Content](../product-requirements/2026-10-18-agent-assisted-sync.md)).
- [ ] Run in `justdavis` with content from `justdavis-private`, the skill showed the complete diff
        and created nothing until the maintainer confirmed it
        (from [Agent-Assisted Sync of Shared Content](../product-requirements/2026-10-18-agent-assisted-sync.md)).
- [ ] After those pull requests merged, a run in each direction created nothing
        (from [Agent-Assisted Sync of Shared Content](../product-requirements/2026-10-18-agent-assisted-sync.md)).
- [ ] The five human decisions are recorded in the README's notes and carried out by the pull
        requests that record them.
- [ ] The maintainer's notes on the skill's speed, cost, and reliability are in the pull request,
        and this plan has been re-read against them
        (from [Agent-Assisted Sync of Shared Content](../product-requirements/2026-10-18-agent-assisted-sync.md)).

### M2 — Exact Comparison and the Reference Check

**Deliverable:** one command reports, per shared path, exactly how the two repositories stand,
  and another reports every dangling reference from shared content;
  the skill starts from the report.

**Deferred:** delivery by a tool; declared divergences.

**In scope:**

- `.lockstep/shared.toml`, replacing the README's list as the declaration the tool reads;
    the README keeps the explanation and the plain-word notes.
- `mise-tasks/lockstep/compare` and `mise-tasks/lockstep/check-refs`, with the shared package
    beside them, as the design specifies: refs on both sides, the four statuses, dirty trees,
    failures as failures, structured output, and the one exit rule.
- `mise-tasks/lockstep/test` and the fixture tests, wired into the root `ci` task.
- The skill revised to consume the report rather than survey.

**Acceptance criteria:**

- [ ] For each declared path the report gives exactly one of identical, differs,
        missing in the working repository, or missing in the other
        (from [Exact Comparison of Shared Content](../product-requirements/2026-10-18-exact-comparison.md)).
- [ ] Each side's ref is recorded and can be overridden, and uncommitted changes are reported and
        excluded (from [Exact Comparison of Shared Content](../product-requirements/2026-10-18-exact-comparison.md)).
- [ ] A failure to compare is never reported as identical, and the command's own failure is
        distinguishable from any result
        (from [Exact Comparison of Shared Content](../product-requirements/2026-10-18-exact-comparison.md)).
- [ ] `lockstep:check-refs` reports every dangling link, `@`-import, and skill pointer with its file
        and line, and passes in both repositories after #44 has merged
        (from [Exact Comparison of Shared Content](../product-requirements/2026-10-18-exact-comparison.md)).
- [ ] The skill explains and carries exactly the differences the report lists
        (from [Exact Comparison of Shared Content](../product-requirements/2026-10-18-exact-comparison.md)).
- [ ] `lockstep:test` passes in `ci`, on fixture repositories built at test time.

### M3 — Exact Delivery

**Deliverable:** the skill writes what it proposes into an output directory, and one command turns
  it into branches and pull requests, byte for byte, after a dry run;
  the publication confirmation is the tool's.

**Deferred:** declared divergences.

**In scope:**

- The output directory: a proposal and one unit per pull request, each with its changes, title,
    description, base ref, and provenance.
- `mise-tasks/lockstep/deliver` as the design specifies: the dry run, choosing units,
    refusing a moved base, a change that no longer applies, or a path outside the declaration,
    checking references before opening, the confirmation prompt that nothing skips,
    and finding its own pull requests on a later run.
- The skill revised to write units and stop.
- Fixture tests and the README's delivery section.

**Acceptance criteria:**

- [ ] The dry run prints every branch and pull request with content and creates nothing;
        run for real and then again, the second run creates nothing new and updates a changed unit
        (from [Exact Delivery of a Sync](../product-requirements/2026-10-18-exact-delivery.md)).
- [ ] The tool refuses a unit whose base has moved or whose changes no longer apply, and a unit
        naming a path outside the declaration, saying what is wrong
        (from [Exact Delivery of a Sync](../product-requirements/2026-10-18-exact-delivery.md)).
- [ ] References from a unit's content are checked before its pull request opens
        (from [Exact Delivery of a Sync](../product-requirements/2026-10-18-exact-delivery.md)).
- [ ] In `justdavis`, a unit with content from `justdavis-private` shows its complete diff and is not
        delivered until the maintainer confirms, and no option skips that
        (from [Exact Delivery of a Sync](../product-requirements/2026-10-18-exact-delivery.md)).

### M4 — Declared Divergences and Shared Parts of Files

**Deliverable:** substitutions, declines, and shared parts of files declared in each repository's
  `.lockstep/local.toml`, applied by the comparison before comparing and by delivery when writing,
  so that no declared difference is ever reported or re-judged.

**Deferred:** path mappings.

**In scope:**

- `.lockstep/local.toml`: substitutions, declines with a reason and the upstream commit they were
    decided against, and shared parts with start and end matchers, as the design specifies.
- The comparison and the delivery tool revised to honor them, with the matcher rule and the
    changed-since note; fixture tests for each form.
- The README's plain-word notes migrated into entries, and the real mixed files that were not split
    in the first milestone declared as shared parts.
- The skill revised to record a decision in the pull request that carries it out.

**Acceptance criteria:**

- [ ] A declared substitution, decline, or shared part is applied before comparison and never
        reported as a difference
        (from [Declared Divergences and Shared Parts of Files](../product-requirements/2026-10-18-declared-divergences.md)).
- [ ] A declined path is reported as declined, and the comparison says when its source has changed
        since the decline
        (from [Declared Divergences and Shared Parts of Files](../product-requirements/2026-10-18-declared-divergences.md)).
- [ ] A shared part is compared on its own and written in place, leaving the rest of its file as it
        was (from [Declared Divergences and Shared Parts of Files](../product-requirements/2026-10-18-declared-divergences.md)).
- [ ] A matcher that matches more or fewer than once is an error
        (from [Declared Divergences and Shared Parts of Files](../product-requirements/2026-10-18-declared-divergences.md)).
- [ ] Each entry is recorded in the pull request that carries out its decision, and when, why, and
        by whom can be read from history
        (from [Declared Divergences and Shared Parts of Files](../product-requirements/2026-10-18-declared-divergences.md)).

### M5 — Renamed and Moved Shared Content

**Deliverable:** content shared at different paths in the two repositories, or moved between
  files, is compared as one thing and landed as a rename by the tools.

**Built only on evidence.**
If the first milestone's notes and the experience of the three that follow show the agent handling
  renames well enough, this milestone is closed as not planned and its requirement stays a draft.

**In scope:**

- A path mapping in the declaration, followed by the comparison and by delivery.
- Recognition of a rename or a move since the last sync from history, proposed as a rename or a
    mapping as the maintainer chooses.
- Fixture tests and the README's section on mapped paths.

**Acceptance criteria:**

- [ ] A mapped pair is reported as one entry and delivered to the mapped path
        (from [Renamed and Moved Shared Content](../product-requirements/2026-10-18-renamed-and-moved-content.md)).
- [ ] A file renamed on one side since the last sync is proposed as a rename or a mapping, and both
        halves of a move stay in one pull request
        (from [Renamed and Moved Shared Content](../product-requirements/2026-10-18-renamed-and-moved-content.md)).
- [ ] Local references to renamed shared content are updated by the tools in the same pull request
        (from [Renamed and Moved Shared Content](../product-requirements/2026-10-18-renamed-and-moved-content.md)).

## Explicitly Deferred (Out of Scope for This Plan)

- **Scheduled or unattended runs.**
  The vision keeps a maintainer at the keyboard for every sync.
- **A third repository.**
  The two-peer model has no hub; if a third repository ever shares content, the declaration's shape
    is revisited first, as the design says.
- **A declared form for broad-strokes entries** such as the root `mise.toml`,
    which stay the agent's judgment until evidence says a declared form would help.
- **Any stored credential or GitHub App.**
  None is planned; the maintainer's own authorization is sufficient.
- **Hardening of the mention-responder workflow**, which reads comments from anyone;
    outside this design and tracked in
    [#54](https://github.com/justdavis-family/justdavis/issues/54).
- **The analyses template** ([#42](https://github.com/justdavis-family/justdavis/issues/42)),
    **the test-coverage criteria altitude**
    ([#43](https://github.com/justdavis-family/justdavis/issues/43)),
    and **whether a requirement's checkboxes are ever ticked**
    ([#45](https://github.com/justdavis-family/justdavis/issues/45)),
    filed along the way and unrelated to delivery.
